Issue reminders

Repeat notifications for active, unacknowledged issues through enabled Telegram and WhatsApp Business channels. Reminders stop when acknowledged or recovered. Paused, stale or suppressed checks do not send reminders.

Import service library?

Existing project services, device service defaults and monitoring history remain unchanged.

Acknowledge issue?

This moves the issue to the acknowledged list and stops reminder notifications. Monitoring continues until the issue recovers.

Unacknowledge issue?

This removes the acknowledgement. Unresolved issues return to Active, or Suppressed when monitoring is unavailable. Recovered issues remain in Resolved. Eligible reminder notifications resume after the configured interval, subject to notification pause and flap protection.

Remove service from host?

This stops monitoring this service on this host. Historical readings are retained. Other hosts and reusable library definitions are unchanged.

Delete deployment?

This permanently deletes the deployment and all its readings, issues, acknowledgement records and related notification records from the database.

The project, inventory devices, service configuration and other deployments are kept. This cannot be undone without restoring a backup.

Resume deployment?

This continues the deployment's retained history and issue numbering using the project's current device and service configuration. Fresh checks are required.

Monitoring and notifications start paused. Choose Resume all monitoring to begin checks, then Resume notifications when ready.

Start a new deployment?

This starts a new deployment with a fresh monitoring history and issue list. Previous deployment data remains stored, but is no longer shown in the current dashboard.

Monitoring and notifications start paused. Choose Resume all monitoring to begin checks, then Resume notifications to enable Telegram and WhatsApp delivery.

To continue a paused deployment with its existing history, choose Cancel and use Resume all monitoring.
